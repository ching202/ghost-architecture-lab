      Four architectural assumptions checked against evidence
      Assumption to checkVerified findingEvidence
      01Each box is a microservice.Core’s API, frontend, and backend modules share one Node.js process. Admin executes in the browser. Logical modules and network services are different boundaries.Runtime architecture ↗
      02Redis is mandatory.Internal caches default to memory; Redis adapters are optional. MySQL is the durable database. HTTP caching is configured separately.Cache configuration ↗

      TRADE-OFF / 01

      Simple deployment,
      shared failure boundary.

      A single core process keeps calls local and deployment straightforward. Its modules also share runtime resources and availability. Splitting services adds operational and network costs.

      TRADE-OFF / 02

      Flexible frontends,
      more client decisions.

      The Content API lets a custom frontend consume public content. That flexibility introduces decisions about rendering, caching, deployment, and keeping content fresh.

      What AI contributed

      OpenAI Codex generated this explorer, the publishing prototype, tests, and documentation. A research subagent checked official sources. Customizations include an explicit process boundary, separate read/write paths, failure injection, defensive storage, accessible controls, and a QA evidence export.

      The application does not put Admin API credentials in a browser. Its local storage is a teaching convenience and is not production access control.
